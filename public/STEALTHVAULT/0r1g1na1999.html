Technical Documentation

What STEALTHVAULT does

STEALTHVAULT takes one or more files, packs them into a single archive, encrypts that archive with AES-256-GCM, and hides the resulting ciphertext inside the pixels of an ordinary image. The image still opens in any viewer and looks the same, but the ciphertext can only be recovered — and only decrypted — with the correct password.

Cryptographic pipeline

  1. Pack — selected files become a SVB1 bundle containing each file's name, MIME type, size and bytes.
  2. Derive — the password is stretched with PBKDF2-HMAC-SHA256 at 310,000 iterations using a fresh 16-byte random salt.
  3. Encrypt — the bundle is encrypted with AES-256-GCM using a fresh 12-byte random IV. The 44-byte container header is passed as additional authenticated data, so any header tampering causes decryption to fail.
  4. Embed — the container is written into the least-significant bit of the R, G and B channels of fully opaque pixels, after a 13-byte stego header (SVSTG001 + version + payload length).
  5. Export — the canvas is encoded as lossless PNG, preserving every bit exactly.

Container format (.svlt v1)

offset  size  field
0       4     magic "SVLT"
4       1     version = 1
5       1     kdf id  = 1 (PBKDF2-HMAC-SHA256)
6       1     cipher  = 1 (AES-256-GCM, 128-bit tag)
7       1     reserved = 0
8       4     PBKDF2 iterations (uint32 big-endian)
12      16    salt
28      12    IV
40      4     ciphertext length including 16-byte tag (uint32 BE)
44      ...   ciphertext || GCM tag

AAD = bytes 0..43 of the header

Bundle format (SVB1, encrypted payload)

0       4     magic "SVB1"
4       1     version = 1
5       3     reserved = 0
8       4     file count (uint32 BE)
per file:
  4     name length,  name (UTF-8)
  4     MIME length,  MIME (UTF-8)
  4     data length (uint32 BE)
  ...   data bytes

Steganography format (image payload)

0       8     magic "SVSTG001"
8       1     version = 1
9       4     container length (uint32 BE)
13      ...   container bytes

Capacity = floor(opaque_pixels * 3 / 8) bytes
Bit order: R LSB, G LSB, B LSB, then next opaque pixel.

Known limitations

  • PNG only for output. JPEG is lossy and re-encoding destroys LSB data. JPEG covers are accepted but always converted to PNG on output.
  • Capacity. Roughly 0.375 bytes per opaque pixel. A 1920×1080 cover holds about 760 KB of ciphertext. Large videos will not fit.
  • Metadata stripping. Any tool that re-saves, resizes, crops or compresses the protected image will destroy the hidden payload.
  • No password recovery. There is no backdoor, hint or key escrow. A lost password means permanently lost data.
  • Transparency. Pixels with alpha below 255 are skipped, because browsers may round their colour values. Heavily transparent covers have less capacity.
  • Image size. Images above 16.7 megapixels are rejected to stay within browser canvas limits (especially on mobile Safari).
  • Steganography is not undetectability. STEALTHVAULT hides data from casual inspection, not from statistical steganalysis. It protects confidentiality through encryption, not through invisibility.

How to run locally

  1. Save the file as index.html.
  2. Open it directly in Chrome, Firefox, Edge or Safari — file:// is a secure context, so Web Crypto works.
  3. For deployment, host it on any static host (Vercel, Netlify, GitHub Pages) over HTTPS.

Frequently Asked Questions

What is STEALTHVAULT?

STEALTHVAULT is a free browser-based security tool by PROBOY that encrypts files with AES-256-GCM and hides them inside ordinary PNG images using pixel-level steganography. The resulting image still opens normally, but only someone with the correct password can recover the hidden files.

What is image steganography?

Image steganography is the practice of storing hidden data inside an image file. STEALTHVAULT uses LSB (least-significant-bit) steganography: it replaces the lowest bit of each colour channel in fully opaque pixels with one bit of encrypted data. The change is far too small for the human eye to detect, and PNG's lossless compression preserves the bits exactly.

How can I hide a ZIP file inside a PNG?

Open the Hide tab, choose a PNG or JPEG cover image, add your ZIP file as a secret file, and enter a strong password. STEALTHVAULT packs the files, encrypts them with AES-256-GCM, and writes the ciphertext into the image's pixel data. You then download a new PNG that looks identical to the original but contains the encrypted ZIP.

How do I recover hidden files?

Open the Extract tab and select the STEALTHVAULT image (or a .svlt container). STEALTHVAULT reads the hidden payload, asks for your password, verifies the GCM authentication tag, and then lists the recovered files with their original names, types and sizes so you can save them individually or as a ZIP.

Is STEALTHVAULT safe?

STEALTHVAULT uses the browser's native Web Crypto API with AES-256-GCM authenticated encryption, PBKDF2-HMAC-SHA256 key derivation at 310,000 iterations, a fresh random salt and IV for every operation, and the container header is authenticated as additional data. Passwords are never stored and never leave your device.

Are my files uploaded to a server?

No. STEALTHVAULT has no backend. Every file is read, encrypted, embedded and decoded inside your browser tab using the File API, Canvas API and Web Crypto API. You can disconnect from the internet after the page loads and it will keep working.

What happens if I forget my password?

There is no recovery. STEALTHVAULT does not store your password and contains no backdoor or master key. Without the exact password the AES-256-GCM authentication tag cannot be verified and the payload stays permanently encrypted. Always keep an independent backup of your password.
